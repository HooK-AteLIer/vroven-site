## Что должно заработать

Сейчас на телефонах (условия `GATES` в `hero-scrub.js`: ширина ≤ 767, портрет ≤ 1024, портрет с касанием, низкий ландшафт с касанием), с file:// и при reduced-motion герой статичный (готовая кухня). Заказчик хочет на телефоне тот же эффект: бетон → отделка → мебель по прокрутке. Десктопный скраб видео не менять.

Решение, одобренное заказчиком:

1. **Основной режим — последовательность кадров на `<canvas>`** (приём Apple). Из `media-raw/hero2/hero-raw-v2.mp4` (склейка 11,83 с, 1912×1080; если её нет — из `site/assets/video/hero-scrub.mp4`) нарезать ≈72 кадра (≈6 fps), обрезка под вертикальный экран по центру стены с кухней (ориентир 3:4 или 9:16 — подобрать так, чтобы на 390×844 стена, светильники и остров были в кадре; можно чуть левее центра, чтобы край окна был виден), ширина ≈720 px, WebP качество ≈70; суммарно ≤ ~3 МБ. Файлы `site/assets/img/hero/frames/f001.webp …`.
   - Загрузка: первый кадр — сразу (он же постер), затем ключевые кадры через один/через четыре (грубая сетка), потом остальные; при прокрутке рисовать ближайший загруженный кадр. Не грузить кадры на десктопе.
   - Отрисовка в `requestAnimationFrame`, только при изменении кадра; canvas по `devicePixelRatio` (не выше 2), `object-fit: cover` логикой рисования.
   - Те же полосы текста (`data-band`) и скримы, что на десктопе: прогресс героя один и тот же.
2. **Лёгкий режим — три картинки с плавной сменой по прокрутке** (черновая → чистовая → кухня, кроссфейд по прогрессу героя), если: `navigator.connection.saveData`, `effectiveType` = 'slow-2g' | '2g' | '3g', или `prefers-reduced-motion` (при reduced-motion — без плавности, просто смена по фазам или статичная кухня; на усмотрение, но без движения). Картинки — кадры из той же обрезки, ≤ ~120 КБ каждая.
3. **file://** — как сейчас статичный герой (fetch кадров может не работать) — допустимо.
4. Чистую логику (прогресс → номер кадра, порядок подгрузки, выбор режима по признакам сети/настроек, кроссфейд-веса для трёх картинок) вынести в функции с `module.exports` и покрыть тестами (сначала красные).
5. `site/README.md`: рецепт нарезки кадров ffmpeg.

## Критерии приёмки

- [ ] На 390×844 и 375×812 (эмуляция мобильного) при прокрутке героя видно: бетон → штукатурка/пол → чистовая → мебель → кухня; обратная прокрутка отматывает; скриншоты 0/25/50/75/100 % в отчёте
- [ ] Первый кадр виден сразу; суммарный вес кадров ≤ ~3 МБ; на десктопе кадры не загружаются (проверить сетевые запросы)
- [ ] С эмуляцией Save-Data / медленной сети включается режим трёх картинок; с reduced-motion — без движения
- [ ] Подписи героя на телефоне читаются на всех фазах; без горизонтального скролла; консоль без ошибок
- [ ] Десктопный скраб видео работает как раньше; `node --test` зелёный
