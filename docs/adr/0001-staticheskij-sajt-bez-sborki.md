# 0001. Статический сайт без сборки, классические скрипты

## Контекст

Заказчик получает одну папку `site/`, которую открывают двойным щелчком и выкладывают на GitHub Pages или обычный хостинг. Часть логики (раскладка кухни, цены, текст заявки) нужно проверять тестами в Node.

## Решение

Сайт пишется на чистых HTML, CSS и JS без npm, сборщиков и фреймворков. Скрипты подключаются как обычные `<script defer>` в фиксированном порядке и делят одно пространство имён `window.VROVEN`. Чистые модули дополнительно умеют экспортировать себя для Node. Шрифты берутся только из Google Fonts, скриптов с CDN нет.

## Почему

- ES-модули отвергнуты: браузер не грузит их с `file://`, а предпросмотр двойным щелчком нужен заказчику.
- npm и сборка отвергнуты: это ломает стандарт 10k (одна папка, деплой одной командой) и требует от заказчика окружения, которого у него нет.
- Скрипты с CDN отвергнуты: сайт должен работать из одной папки, а чужой адрес становится ещё одной точкой отказа.

## Последствия

- Порядок подключения скриптов (`data.js`, `core.js`, `lead.js`, модули страницы) держится на дисциплине. Перепутанный порядок ломает страницу молча.
- Общее пространство имён: два модуля могут перезаписать друг друга, ничто этого не поймает.
- Шапка и подвал размечены копией в HTML каждой страницы. Правка навигации означает правку четырёх файлов.
- Чистые модули несут условный экспорт для Node. Забытая строка в конце файла означает, что тест не видит модуль.
- Перейти на сборку и модули позже можно, но придётся менять каждую страницу и каждый модуль сразу.
